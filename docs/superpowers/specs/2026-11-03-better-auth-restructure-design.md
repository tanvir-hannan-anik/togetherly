# Togetherly: better-auth migration + lean restructure

## Context

Togetherly is a community-events app (Next.js client in this repo + Express/MongoDB
server in `server/`). It currently uses a hand-rolled bcrypt + cookie-session auth
system on both sides. The user wants the whole codebase brought in line with the
structure and conventions of two reference repos (`ProgrammingHero1/b14-wanderlust-client`
and `b14-wanderlust-server`), which use **better-auth** (MongoDB adapter, JWT plugin)
on the client and JWKS-based bearer-token verification on the Express server. The user
also wants GitHub OAuth added (not present in the reference), the server simplified to
match the reference's lean single-file style, requirement gaps against the assignment
brief closed, and unrelated Playwright test scaffolding removed.

Decisions already made with the user (via clarifying questions):
- `server/` stays inside this repo — simplified in place, not moved.
- Full auth replacement: better-auth + JWT + JWKS end-to-end, including GitHub OAuth.
- Server is simplified to the lean reference style (drop rate limiting, strict origin
  checks, pagination) but keeps assignment-required validation (future-date check,
  event-type whitelist, ownership checks on update/delete).
- Remove `tests/`, `playwright.config.ts`, `test-results/`, the `test:e2e` script, and
  the `@playwright/test` devDependency. `AGENTS.md` is left untouched (it's
  auto-regenerated by `next dev`).

## Goals

1. Replace the custom auth system with better-auth (email/password + GitHub OAuth),
   using the JWT plugin + JWKS verification pattern from the reference repos.
2. Simplify `server/index.js` to a lean, single-file Express app matching the
   reference's shape, while keeping assignment-mandated validation.
3. Restructure client file/folder naming to match the reference conventions
   (lowercase-kebab components, grouped folders like `home/`, `events/` under
   `src/components`).
4. Close requirement gaps found against the assignment brief:
   - Navbar profile-picture dropdown (Create Event / Manage Events / Joined Events),
     with hover-to-reveal display name.
   - Home page Gallery section (static) and Newsletter section (non-functional UI).
   - Use better-auth's `image` field to satisfy the register page's photoURL field and
     the "profile view/update" optional feature.
5. Remove Playwright test scaffolding.

## Non-goals

- No email verification, no forgot-password flow (explicitly excluded by the
  assignment brief).
- No change to the overall visual design/theme already in place, beyond adding the
  missing sections/dropdown called out above.
- No pagination, rate limiting, or other production hardening beyond what the
  assignment requires — intentionally simplified to match the reference.

## Design

### 1. Data model

Keep the existing shape — it already matches the reference's `destination`/`booking`
mapping:

- `events` collection: `title, type, thumbnail, location, date, description, duration,
  organizerId, organizerName, participants[], createdAt`. `organizerId`/`organizerName`
  and participant emails are sourced from the better-auth session, not client input.
- No separate "joined events" collection — participation stays modeled as
  `participants: string[]` (user id) on the event document, which already satisfies
  "store the data along with the event and user data" for Join Event.
- Users, sessions, and OAuth accounts are now owned entirely by better-auth's MongoDB
  adapter (new collections it manages itself: `user`, `session`, `account`,
  `verification`, `jwks`). The app no longer defines its own `users`/`sessions`
  collections or `passwordHash` field.

### 2. Client auth (better-auth)

New files, modeled directly on the reference:

- `src/lib/auth.ts` — `betterAuth({ database: mongodbAdapter(...), emailAndPassword:
  { enabled: true }, socialProviders: { github: { clientId, clientSecret } }, plugins:
  [jwt()], session: { cookieCache: { enabled: true, strategy: 'jwt', maxAge: 7d } } })`.
- `src/lib/auth-client.ts` — `createAuthClient({ baseURL: BETTER_AUTH_URL, plugins:
  [jwtClient()] })`.
- `src/app/api/auth/[...all]/route.ts` — `toNextJsHandler(auth)`.
- `src/proxy.ts` — redirects to `/login` when there's no session; `matcher` covers
  `/events/create`, `/events/:id/edit`, `/my-events`, `/joined-events`.
- `src/lib/getTokenFromServer.ts` / `getTokenFromClient.ts` — fetch the JWT (server
  components use the server helper; client components use the client helper) to attach
  as `Authorization: Bearer <token>` on calls to the Express API.

Removed: `AuthProvider.tsx`'s custom fetch-based session state, `RequireAuth.tsx`'s
manual loading/error UI (replaced by `proxy.ts` for route protection; any client-side
"am I logged in" check uses `authClient.useSession()` directly).

Login/Register pages are rebuilt on `authClient.signIn.email`, `authClient.signUp.email`,
and `authClient.signIn.social({ provider: "github" })`. Keep: password rule (one
uppercase, one lowercase, length ≥ 6) enforced client-side before calling better-auth,
with a toast/error message on failure; toast/SweetAlert on successful login/register
(per assignment brief). Register form still collects `name`, `email`, `photoURL`,
`password` — `photoURL` is passed as `image` to `authClient.signUp.email`.

GitHub OAuth app callback URL: `http://localhost:3000/api/auth/callback/github`
(standard better-auth social-provider callback path — no custom route needed).

### 3. Server (Express) simplification

Rewritten `server/index.js`, same shape as the reference:

- Drop: `bcryptjs`, `cookie-parser`, `express-rate-limit` dependencies; the
  `users`/`sessions` collections; `/auth/signup`, `/auth/login`, `/auth/me`,
  `/auth/logout` routes; the strict-origin-header check; rate limiters; pagination on
  `GET /events`.
- Add: `jose`'s `createRemoteJWKSet` + `jwtVerify` against
  `${CLIENT_URL}/api/auth/jwks`; a `verifyToken` middleware (401 if missing/invalid)
  applied to every route that needs the caller's identity (create/update/delete event,
  join/leave, my-events, joined-events). The verified JWT payload's `sub`/`email`
  (better-auth JWT claims) replace `req.user` from the old session lookup.
- Keep: future-date validation, event-type whitelist, title/description/location
  length checks, thumbnail URL validation, ownership checks on update/delete (all
  required by the assignment brief), `GET /events` (upcoming only, no pagination),
  `GET /events?limit=6` style call from the home page (or a dedicated
  `/featured-events` route mirroring the reference's `/featured-destinations`), 
  `GET /my-events`, `GET /joined-events` (sorted by date), `/stats`, `/newsletter`
  (collects email only, no functionality beyond that per brief).

### 4. Client restructure (naming/layout)

Rename to match reference conventions (lowercase-kebab, grouped folders):

- `src/components/HomePage/*` → `src/components/home/*` (`banner.tsx`, `featured.tsx`,
  `gallery.tsx` (new), `newsletter.tsx` (new), `navbar.tsx`, `footer.tsx` lifted to
  `src/components/` root like the reference).
- `src/components/EventCard.tsx`, `EventBrowser.tsx`, `EventDetails.tsx`,
  `EventEditor.tsx`, `EventForm.tsx`, `EventImage.tsx`, `DeleteEventButton.tsx`,
  `UpComingEvantCard.tsx` → grouped under `src/components/event/*` with kebab names
  (`event-card.tsx`, `event-browser.tsx`, `event-details.tsx`, `event-editor.tsx`,
  `event-form.tsx`, `delete-event-dialog.tsx`, matching the reference's
  `destination/EditDestinationDialog.tsx` / `DeleteDestinationDialog.tsx` pattern).
- `PersonalEvents.tsx`, `Impact.tsx`, `Feedback.tsx` → kept at `src/components/` root,
  renamed to kebab-case.
- Routes stay as-is (`/events`, `/events/create`, `/events/[id]`, `/events/[id]/edit`,
  `/my-events`, `/joined-events`, `/login`, `/signup`, `/impact`); `/upcoming-event`
  (singular, currently unused/duplicate of `/events`) is removed if confirmed dead.

### 5. Navbar profile dropdown (requirement gap)

Replace the current letter-avatar + direct logout button with: profile image (from
better-auth session `image`, fallback initial) that on hover shows a tooltip with the
display name, and on click opens a dropdown with **Create Event**, **Manage Events**
(→ `/my-events`), **Joined Events**, and **Logout**. Unauthenticated state keeps the
existing "Login" link.

### 6. Home page gaps (requirement gap)

- **Gallery section**: new static component, grid of community-service photos (reuse
  existing `/public/image` assets or add a few placeholders), no backend involvement.
- **Newsletter section**: new static component with an email input + subscribe button
  styled to match the rest of the site; per the brief, no functionality is required,
  but since the server already exposes `/newsletter`, wiring it is a one-line win — it
  will be wired to that existing endpoint rather than left as a dead form.

### 7. Environment variables

Client `.env.local` (`.env.example` updated to match):
`MONGODB_URI`, `BETTER_AUTH_URL=http://localhost:3000`, `BETTER_AUTH_SECRET`,
`GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `NEXT_PUBLIC_API_URL=http://localhost:8000`.

Server `.env` (`server/.env.example` updated to match):
`MONGODB_URI`, `CLIENT_URL=http://localhost:3000`, `PORT=8000`.

(`MONGODB_URI` replaces the current `MONGODB_URL`/`MONGODB_DB` pair — one connection
string, database name taken from the URI path, matching the reference.)

### 8. Removals

- `tests/community.spec.ts`, `tests/visual.spec.ts`, `playwright.config.ts`,
  `test-results/` (untracked build output — deleted locally, nothing to un-ignore).
- `package.json`: `test:e2e` script, `@playwright/test` devDependency.
- `server/package.json`: `bcryptjs`, `cookie-parser`, `express-rate-limit`
  dependencies; add `jose`.
- `src/components/AuthForm.tsx`, `AuthProvider.tsx`, `RequireAuth.tsx` (superseded by
  better-auth client/`proxy.ts`), `src/hooks/useApi.ts` if it turns out to be
  session-polling boilerplate superseded by `authClient.useSession()` (confirm during
  implementation — keep if it's still useful as a generic fetch hook).

## Testing

No Playwright/e2e tests (removed by this spec). Manual verification during
implementation: register (email/password), login (email/password), login via GitHub,
create event (rejects past dates), edit/delete own event (rejects editing others'),
join/leave event while logged out (redirected) and logged in, home page shows 6
soonest upcoming events + gallery + newsletter, navbar dropdown shows correct links
and hover name, theme toggle still works.

## Open items for implementation time

- Confirm `/upcoming-event` route is genuinely unused before deleting it.
- Confirm whether `src/hooks/useApi.ts` is still needed post-migration.
- GitHub OAuth app client id/secret must be created by the user in GitHub's developer
  settings (callback `http://localhost:3000/api/auth/callback/github`) and placed in
  `.env.local` — not something this change can provision automatically.
